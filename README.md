# Iron Log

A private workout, weight, body-measurement and nutrition journal. Built as a
single-page installable PWA — all data lives in your browser's `localStorage`,
works fully offline, and can be exported to JSON anytime.

## Features

- **Track** weight, body measurements, meals (calories + macros) and workouts
  (sets/reps/volume, routines, session queues).
- **Calculators** (Tools tab, also linked from Weight / Body / Nutrition):
  - **BMI** (WHO categories, healthy weight range, BMI Prime, Ponderal index)
  - **Body Fat** (U.S. Navy method + BMI method, ACE categories, Jackson &
    Pollock ideal-for-age, log results to your weight entry)
  - **BMR** (Mifflin-St Jeor, Revised Harris-Benedict, Katch-McArdle)
  - **Calories / TDEE** (6 activity levels, maintain/cut/bulk targets)
  - **Macros** (Balanced / Low-carb / High-protein / Keto splits with a
    protein floor — one tap sets your Nutrition daily targets)
  - **Ideal Weight** (Hamwi, Devine, Robinson, Miller + healthy BMI band)
- Calculators pre-fill from your **profile** (height, sex, birth date — set in
  Settings) and your latest logged weight/measurements; all inputs stay in sync
  across the six tools.
- **Dark mode** — System / Light / Dark (Settings), with a pastel-dark palette
  and a subtle film-grain background.
- **Goal weight & trend** — set a goal weight in Settings; the dashboard shows
  progress and projects a date to reach it from your recent trend. The weight
  chart has a 7-day trend line and a kg-per-week rate chip.
- **Nutrition insights** — a trailing 7-day average against your daily targets,
  plus **favorite meals** (tap ♥ on any meal, then add it again in one tap from
  the Log view).

## Stack

- [Vite](https://vite.dev) + React 18 — build tooling
- [recharts](https://recharts.org) — charts
- [lucide-react](https://lucide.dev) — icons
- [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) — web app manifest +
  Workbox service worker for offline support and installability

## Local development

```bash
npm install
npm run dev      # start dev server (http://localhost:5173)
```

## Production build

```bash
npm run build    # regenerates PWA icons (prebuild) + builds into dist/
npm run preview  # serve the production build locally
```

PWA artifacts produced in `dist/`:

- `index.html`, `assets/*` — the app shell (fully precached by the service worker)
- `sw.js` + `workbox-*.js` — service worker (precache + Google Fonts runtime cache)
- `registerSW.js` — injected script that registers the service worker
- `manifest.webmanifest` — install manifest (standalone, brand theming, icons)
- `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`
  — generated by `scripts/generate-icons.js` (dependency-free PNG writer)

## Deploy to Netlify

The repo is already configured via `netlify.toml` (build command `npm run build`,
publish dir `dist`, Node 22, SPA fallback with service-worker passthrough rules).

**Option A — Git:** push this folder to a Git repo and connect it to Netlify
(New site → Import an existing project). Nothing else to configure.

**Option B — CLI / drag-and-drop:**

```bash
npm i -g netlify-cli
netlify login
netlify deploy --prod --dir=dist
```

or drag-and-drop the `dist/` folder into the Netlify drop section.

### Verify the PWA

1. Open the deployed site in Chrome.
2. DevTools → Application → Service Workers: `sw.js` should be **activated**.
3. DevTools → Application → Manifest: manifest should load with valid icons.
4. Reload offline (DevTools offline / airplane mode) — the app still opens.
5. The install icon appears in the address bar; iOS users can
   "Add to Home Screen" (theme-color, standalone display, and `apple-touch-icon`
   are wired up).

> Note: any data in a previous Claude.ai artifact environment is sandboxed to
> that origin and cannot be migrated — the deployed app starts fresh.

## Storage

`src/storage.js` is the single storage adapter: `loadKey(key, fallback)` and
`saveKey(key, value)` over `localStorage` (JSON per key). All Iron Log data is
whole-blob key/value JSON, comfortably within the ~5MB quota. Swapping to
IndexedDB later would only require changing this one file.
